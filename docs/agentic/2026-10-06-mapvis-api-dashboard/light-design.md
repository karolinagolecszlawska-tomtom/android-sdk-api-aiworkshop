## Why & what

The MapVis team cannot see which downstream Android apps consume each of its `go-sdk-android` artifacts, how stable the consumed packages are, or how far each app lags behind the SDK releases. This change adds a generator to this (empty) repo that reads `go-sdk-android` and the three consumer repos read-only via `gh api` and writes a static HTML dashboard grouped by package. It covers rules M1–M5, S1, S3, S4, S5, N1 and N2 of [ACCEPTANCE.md](../../../ACCEPTANCE.md); S2 (Alpha/Beta entry dates) and the weekly refresh are out of this change (D-1).

## How - Program design

A Python 3.11 standard-library package `generator/` (no third-party deps, `unittest` for tests — D-4). Every remote read goes through `gh api` in a subprocess, so the user's existing `gh` auth is reused. `go-sdk-android`'s default branch is `master`.

- `generator/github.py` — `raw(repo, path)` runs `gh api repos/tomtom-internal/{repo}/contents/{path}?ref={branch} -H "Accept: application/vnd.github.raw"`; `tree(repo, branch)` reads `git/trees/{branch}?recursive=1`; `releases()` runs `gh api --paginate "repos/tomtom-internal/go-sdk-android/releases?per_page=100"` and `latest_release()` reads `releases/latest`. GET only (N2). About 55 calls per run, well inside the 5000/h limit (N1).
- `generator/codeowners.py` — parses CODEOWNERS (whitespace-split, `#` comments stripped). `team_paths(team)` returns the patterns naming `@tomtom-internal/lp-mapvis-mapdisplaysdk-android`; `owner_of(path)` applies last-match-wins (gitignore-style globs, `**` supported) to a module directory. A module is in scope when any team pattern matches its directory — in practice all of `/maps/**` (CODEOWNERS:317) — and carries its effective owner as a tag (D-3).
- `generator/modules.py` — module = directory under `maps/` with a `build.gradle.kts` that declares `val artifactId by extra("…")` and `val groupId by extra("…")` (pattern at go-sdk-android `maps/map-display-duo-internal/build.gradle.kts:22-24`); modules without them are unpublished and skipped (D-12). Coordinate = `groupId:artifactId` (not the dir name — `maps/visualization/routing` → `com.tomtom.sdk.maps.visualization:routing`). `api_deps(gradle_text)` matches `^\s*api\(projects\.([\w.]+)\)` (indented KMP source-set blocks included, `implementation`/`testImplementation` ignored), converts each camelCase accessor segment to kebab-case (`projects.maps.mapDisplayCommon` → `maps/map-display-common`) and keeps only in-scope modules.
- `generator/state.py` — parses `api/state.csv` by splitting each line on `;` into 7 fields (`module_name;domain;name;type;state;hasDoc;flavor`; names contain commas). Package = the dot-separated segments of `name` before the first `(` that start lowercase, stopping at the first capitalised segment (`com.tomtom.sdk.map.display.StandardMapRendererCompat.kt…` → `com.tomtom.sdk.map.display`) (D-8). Tallies rows per `(artifact, package, state)` for every state value present — `GA`, `BETA`, `ALPHA`, `EXPERIMENTAL`, `DEPRECATED`, `INTERNAL`, `INTERNAL_AVAILABILITY` each its own column (D-7). A module with no `state.csv` gets the single stability `state unknown` (S5).
- `generator/catalogs.py` — reads a version catalog with `tomllib`, resolves `version.ref` through `[versions]`, keeps libraries whose `module` group is `com.tomtom.sdk.maps` or `com.tomtom.sdk.maps.visualization`, and dedupes by `module` (aliases differ per repo). Consumer catalogs are fixed: `oneapp-android:gradle/libs.versions.toml`, `navapp-automotive:gradle/gosdk-libs.versions.toml`, `r2-navapp:gradle/gosdk-libs.versions.toml` (D-9). A consumer's pinned version is the lowest resolved version among its kept libraries (all three use the single `gosdk` ref today).
- `generator/versions.py` — parses tags matching `^\d+\.\d+\.\d+(-rc\d+)?$` (drafts and `-dev…` tags excluded) and orders them semver-style, `X.Y.Z-rcNN` before `X.Y.Z`. Latest stable = `releases/latest` tag (`2.4.5`, a backport — not the highest semver); latest RC = highest-semver `-rcNN` tag (`2.8.0-rc01`, not the newest by date) (D-10). `behind(pin, baseline, tags)` returns `"ahead of <label>"` when pin > baseline, else the count of tags `t` with `pin < t ≤ baseline` (D-2).
- `generator/build.py` — assembles the model: artifacts (coordinate, module path, owner tag, packages with state tallies), direct pairs from catalogs, one level of transitive pairs (for each directly consumed artifact, its `api_deps` targets not already direct, recorded "via <artifact>") (S1), per-artifact consumer totals over direct + transitive repos, unconsumed artifacts/packages (S3), consumer version rows (M4), docs references as a fixed list `["mapdisplay-for-unity", "devportal-documentation"]`, shown by name only (D-11). Catalogs passed via `--extra-catalog name=path` go to a separate `extra_consumers` key and an "Extra catalogs" section, never into the direct pairs (D-6).
- `generator/redact.py` — `redact(text)` replaces `key=<token>` (token of `[A-Za-z0-9_\-]{8,}`) with `key=***`; applied to every fetched file before parsing and to the final HTML and JSON (M5).
- `generator/html.py` — renders one self-contained `dashboard.html` (inline CSS, no JS dependencies) grouped by package: per package its artifact(s), owner tag, state columns, and consumers (direct, and transitive as "via `<artifact>`"); then sections "Consumer versions", "No consumers", "Docs references", and "Extra catalogs" when present.
- `generator/__main__.py` — CLI `python3 -m generator --out out [--extra-catalog name=path …]`: fetch → build → write `out/data.json`, `out/dashboard.html`, and the fetched `state.csv` files under `out/raw/` (used by the S4 check) (D-5).
- `tests/` — offline unit tests per module on small inline inputs plus `fixtures/old-version.versions.toml`; `tests/test_acceptance.py` reads the generated `out/` and checks M1–M5, S1, S3, S4, S5 (fails with "run `python3 -m generator …` first" when `out/data.json` is missing). `.gitignore` gets `out/` and `__pycache__/`.

Test command: `python3 -m unittest discover -s tests -v` (pytest is not installed).
